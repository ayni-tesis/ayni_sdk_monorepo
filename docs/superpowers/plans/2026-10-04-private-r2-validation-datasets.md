# Private R2 Validation Datasets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let application administrators publish immutable validation dataset ZIP versions to the private production R2 bucket and let an active application's SDK credential download them through a short-lived signed URL.

**Architecture:** Add application-scoped dataset/version records and an R2 storage adapter, then expose authenticated dashboard routes for registration/upload and a Bearer-authenticated SDK manifest route. Follow the existing model-version flow for direct-to-R2 upload, storage-key isolation, and short-lived downloads; extend the application dashboard with metadata and upload progress.

**Tech Stack:** Bun, TypeScript, Hono, Zod/OpenAPI (`packages/api`), Drizzle/Postgres, private R2 through the existing storage helpers, Next.js, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-03-app-validacion-movil-sdk-design.md`

## Global Constraints

- The production bucket remains private.
- Dataset upload and download use temporary URLs generated by the server; R2 object keys and permanent object URLs never appear in API responses. The temporary signed URL is the only object-transfer reference returned to a client.
- Each ZIP contains a manifest with schema version, `datasetId`, partition, source/license, an ordered case list, scenario, `caseId`, relative image path, and SHA-256 for each image.
- Dataset versions are immutable and scoped to one application.
- A valid SDK credential is limited to its active application; missing, foreign, or archived resources must not reveal artifact information.
- Only images whose license permits redistribution for this use may be uploaded; the system records the source and license declaration and does not certify legal compliance.
- The mobile client verifies ZIP and per-image hashes, rejects absolute/traversal paths, and runs measurements from its private local copy without network requests.
- Application result JSONL, input images, and tensors are not uploaded by this feature.

## Review Focus

- A member, foreign application, or archived application must not create or upload a dataset; tests in Task 2 assert role/status responses and that no storage/database write occurs.
- A duplicate dataset name/version/partition or replayed upload completion must not mutate an immutable published version; tests in Tasks 1–2 assert conflict responses and unchanged rows/objects.
- Oversized, absent, or hash-mismatched ZIP objects must not become published versions; tests in Task 2 assert the exact 413/400 responses and cleanup of staging objects.
- A revoked credential or a version outside its application must not return a URL or storage key; tests in Task 3 assert 401/404 responses and no signer call.
- An expired signed URL must not be persisted or exposed as a permanent dataset link; tests in Task 3 assert only a freshly generated URL and expiry are returned.

## File Structure

- `packages/db/src/schema/validation-dataset.ts` defines application-owned dataset and immutable version tables; `schema/index.ts` exports them and the generated migration creates the tables/indexes.
- `apps/server/src/validation-dataset-store.ts` owns database operations and version immutability; `validation-dataset-storage.ts` adapts private R2 upload, download, size, and cleanup operations.
- `apps/server/src/validation-datasets.ts` handles dashboard list/create/upload completion routes; `sdk-validation-datasets.ts` serves SDK manifests. Each has a focused Vitest suite and is registered in `hono-app.ts`.
- `packages/api/src/validation-datasets.ts` defines shared request/response schemas and OpenAPI route descriptions; `src/index.ts` exports them.
- `apps/web/src/app/dashboard/panels/application/validation-datasets.ts` owns HTTP upload orchestration; `validation-datasets-panel.tsx` owns the list/form/progress UI and its tests. `application-detail-panel.tsx` mounts the panel.

## Self-review

- Spec coverage: private versioned R2 objects and upload UI are in Tasks 1–2 and 4; SDK short-lived manifest is in Task 3; route/migration integration is Task 5; license/source declaration is Task 4. Mobile ZIP/hash/path enforcement belongs to the linked mobile plan.
- Type consistency: the route response fields and `datasetVersionId`/SHA/size/URL names are repeated unchanged from Task 2 through Task 5 and the mobile plan.
- Retention: this first release has no dataset/version delete API or automatic expiry for finalized validation objects; they remain available for reproducibility until a separately reviewed operational removal. Release setup must configure R2 to expire uncompleted `staging/<applicationId>/validation-datasets/` objects after 7 days while excluding finalized validation dataset prefixes; completion/error paths remove staging objects immediately.
- Proportion: this plan adds one narrowly scoped resource type by following the established model-version patterns; it does not add a generic asset service or app-result upload path.
